## Purpose

为新闻分类和分页列表提供可预测、可失效的共享缓存，使已提交的新闻业务变更不会继续通过 Redis 向客户端返回过时的分页内容，同时在缓存依赖异常时保持 MySQL 作为唯一事实来源。

## ADDED Requirements

### Requirement: 稳定的新闻分页快照

系统 SHALL 使用稳定且可预测的新闻排序规则生成分类分页结果。每个可缓存分页响应 MUST 在同一数据快照中包含新闻列表、总数和 `hasMore`，不得把缓存列表与不同时刻计算的总数混合返回。

#### Scenario: 重复请求同一未变更页面

- **WHEN** 分类新闻未发生影响列表顺序或成员的已提交变更，客户端重复请求相同 `categoryId`、页码和页大小
- **THEN** 系统返回遵循同一稳定排序规则的等价分页结果

#### Scenario: 缓存分页响应

- **WHEN** 系统命中一个有效的新闻分页缓存
- **THEN** 系统从该缓存响应同时返回列表、总数和 `hasMore`

### Requirement: 新闻分页缓存随业务变更失效

系统 SHALL 为每个新闻分类维护可递增的缓存世代，并将该世代与分类、页码和页大小共同标识分页缓存。新闻新增、删除、切换分类或修改会影响列表成员或排序的字段在数据库提交成功后 MUST 使受影响分类的此前分页缓存不再可读。

#### Scenario: 新增新闻改变首页和后续页

- **WHEN** 一篇新闻已成功写入某分类且其排序位置会影响该分类的分页
- **THEN** 后续读取该分类任意页码时不得返回写入前的分页缓存

#### Scenario: 新闻迁移到其他分类

- **WHEN** 一篇新闻已成功从分类 A 迁移到分类 B
- **THEN** 后续读取分类 A 或分类 B 的任意页码时不得返回迁移前的分页缓存

#### Scenario: 数据库提交失败

- **WHEN** 新闻写入事务未成功提交
- **THEN** 系统不得使该次未提交变更对应的缓存世代成为当前可读世代

### Requirement: 分类缓存随分类数据变更失效

系统 SHALL 使用可失效的分类缓存，并将查询参数纳入缓存身份，或只缓存不带分页歧义的完整分类结果。分类新增、删除或展示字段变更在数据库提交成功后 MUST 使此前分类缓存不再可读。

#### Scenario: 分类展示名称变更

- **WHEN** 一个分类的展示名称已成功更新
- **THEN** 后续分类读取不得返回更新前名称的缓存结果

#### Scenario: 不同分类查询形状

- **WHEN** 两个分类请求使用不同的分页参数
- **THEN** 系统不得因复用同一缓存项而返回另一个查询形状的数据

### Requirement: 缓存未命中与 Redis 故障降级

系统 SHALL 在新闻或分类缓存未命中时从 MySQL 构建结果并使其可供后续读取。Redis 读、写或失效操作不可用时，系统 MUST 继续从 MySQL 返回当前数据，且不得将缓存基础设施错误暴露为新闻读取接口错误。

#### Scenario: Redis 不可用时读取新闻列表

- **WHEN** Redis 在新闻分页读取期间不可用
- **THEN** 系统从 MySQL 返回遵循稳定排序规则的当前分页结果

#### Scenario: Redis 不可用时写入新闻

- **WHEN** 新闻业务变更已成功提交但 Redis 缓存失效暂时失败
- **THEN** 已提交的新闻数据保持有效，系统记录可诊断的失效失败，并在缓存依赖不可用期间从 MySQL 提供读取结果

### Requirement: 空结果与高频字段的缓存边界

系统 SHALL 对有效但为空的分类分页结果采用较短保留时间的缓存策略，避免重复请求持续访问 MySQL。新闻浏览量更新 MAY 在列表缓存保留期内延迟可见；浏览量更新本身 MUST NOT 使整个分类的所有分页缓存失效。

#### Scenario: 重复请求空分页

- **WHEN** 客户端重复请求一个有效但没有新闻的分类分页
- **THEN** 系统可在短期内复用空结果缓存而不重复查询 MySQL

#### Scenario: 新闻浏览量变化

- **WHEN** 一篇新闻的浏览量更新但标题、正文、分类和排序字段未变化
- **THEN** 系统可以在列表缓存过期前返回稍旧的浏览量，且列表成员和排序仍保持一致

### Requirement: 受控写入与运维失效

系统 SHALL 将新闻和分类缓存失效收敛到受控的服务边界。应用内的新闻或分类写入路径 MUST 在数据库提交成功后调用该边界；绕过应用服务的导入或手工数据库修改 MUST 有受控的运维失效入口，以避免继续读取已知旧缓存。

#### Scenario: 应用写路径更新新闻

- **WHEN** 应用内新闻写路径成功提交新增、更新、删除或分类迁移
- **THEN** 写路径调用对应的缓存失效边界后才向调用方报告成功

#### Scenario: 运维导入新闻数据

- **WHEN** 管理员通过受控导入或手工数据库操作变更新闻或分类数据
- **THEN** 管理员可以执行受控缓存失效入口，使后续读取不使用变更前缓存
