## ADDED Requirements

### Requirement: 受约束的中文新闻分块

系统 SHALL 在生成新闻向量前按照中文自然段、句子和子句边界确定性地拆分正文，并使用与 Embedding 模型一致的 token 计数限制每个向量输入。每个 Chunk MUST 保留所属新闻、顺序和原文位置等可追溯信息，且不得依赖模型服务静默截断超长输入。

#### Scenario: 长新闻后部包含相关事实

- **WHEN** 一篇新闻超过 Embedding 模型单次输入上限，且用户问题相关事实位于正文后部
- **THEN** 该事实所在 Chunk 被独立建立向量，并可参与后续语义检索

#### Scenario: 事实跨越普通切分边界

- **WHEN** 相关语义位于相邻段落或句子的边界附近
- **THEN** 系统通过有界重叠保留必要上下文，且每个 Embedding 输入仍不超过配置上限

#### Scenario: 短新闻建立索引

- **WHEN** 新闻标题、简介和正文在单个 Chunk 的有效预算内
- **THEN** 系统生成一个可追溯 Chunk，且不制造内容等价的重复向量

### Requirement: 受预算约束的检索上下文

系统 SHALL 将 Chunk 级候选按新闻聚合，在配置的候选数量、每篇新闻片段上限、最终新闻数量和上下文 token 预算内构造 QA 与 Agent 可消费的上下文。返回给模型和客户端的引用片段 MUST 来源于实际命中的 Chunk，不得固定使用新闻正文开头替代命中内容。

#### Scenario: 同一新闻多个 Chunk 排名靠前

- **WHEN** 候选结果中同一新闻的多个 Chunk 均具有较高相似度
- **THEN** 系统限制该新闻占用的片段数量，并为其他相关新闻保留有界的召回空间

#### Scenario: 检索结果超过上下文预算

- **WHEN** 聚合后的相关 Chunk 总量超过配置的上下文 token 预算
- **THEN** 系统按确定性排序保留预算内的高相关片段，且不在 Chunk 中间产生不可追溯的引用

#### Scenario: 展示新闻引用

- **WHEN** QA 或 Agent 使用语义检索结果生成回答
- **THEN** 客户端收到现有格式的新闻 ID、标题和实际命中片段，且顶层 HTTP 响应结构保持兼容

## MODIFIED Requirements

### Requirement: 本地新闻向量索引

系统 SHALL 使用项目配置的本地 Embedding 服务为可检索新闻生成固定维度的 Chunk 向量，并将每个 Chunk 的向量、新闻标识、Chunk 标识、顺序、原文位置及用于引用的必要元数据持久化到支持向量检索的 Redis 服务。向量数据、新闻缓存数据和 Agent 会话检查点 MUST 使用可区分的索引或键命名空间。

#### Scenario: 为新闻建立向量记录

- **WHEN** 系统为数据库中的新闻建立索引
- **THEN** 每篇可检索新闻拥有一个或多个可按新闻 ID 和 Chunk 标识追溯的向量记录及必要引用元数据

#### Scenario: Redis 服务支持向量索引

- **WHEN** 应用初始化新闻向量索引
- **THEN** Redis 服务提供所需的搜索能力，且不会覆盖新闻缓存或 Agent 会话检查点的数据命名空间

### Requirement: 可重复的新闻索引构建

系统 SHALL 提供受控的全量新闻 Chunk 向量索引构建入口。重复执行该入口 MUST 以当前 `news` 表和当前分块配置为准生成一组完整候选索引，且不得为同一新闻和 Chunk 留下重复的有效记录。新索引只有在构建与完整性验证成功后才能成为读取入口；失败构建不得破坏当前可用索引。

#### Scenario: 首次构建索引

- **WHEN** 管理员在空新闻 Chunk 向量索引上执行全量构建
- **THEN** 当前可检索新闻的有效 Chunk 均可被后续语义查询召回，并报告扫描新闻数与写入 Chunk 数

#### Scenario: 重复构建索引

- **WHEN** 管理员在已有索引上再次执行全量构建
- **THEN** 新读取入口反映当前 `news` 表和分块配置，且同一新闻和 Chunk 只保留一条有效可检索记录

#### Scenario: 候选索引构建失败

- **WHEN** Embedding、Redis 写入或完整性验证在新索引构建期间失败
- **THEN** 当前读取入口保持不变，已存在的有效索引继续提供语义检索

### Requirement: 语义检索与关键词降级

系统 SHALL 优先根据问题与新闻 Chunk 向量的语义相似度召回有界候选，经相似度过滤和新闻级聚合后返回相关新闻、实际命中片段及引用元数据。当本地 Embedding 服务、向量索引或索引数据不可用时，系统 SHALL 降级到现有关键词检索；降级过程 MUST NOT 向客户端暴露基础设施堆栈错误。

#### Scenario: 近义问题召回新闻

- **WHEN** 用户的问题与新闻中的某个正文片段语义相关但不包含相同关键词
- **THEN** 系统优先返回包含该命中片段的有界新闻结果及引用元数据

#### Scenario: 向量能力暂时不可用

- **WHEN** 本地 Embedding 服务、向量索引或索引数据不可用
- **THEN** 系统使用关键词检索继续尝试返回相关新闻，而不是因向量组件错误中断请求

#### Scenario: 两种检索均无结果

- **WHEN** 语义检索与关键词检索都未找到相关新闻
- **THEN** 系统返回空检索结果，且不得创建虚构新闻引用
