# news-semantic-retrieval Specification

## Purpose

为项目内新闻提供可重复构建、可持久化的中文语义检索能力，在本地服务不可用时保持检索服务可降级且不影响现有新闻问答与 Agent 的可用性。

## Requirements

### Requirement: 本地新闻向量索引

系统 SHALL 使用项目配置的本地 Embedding 服务为可检索新闻生成固定维度的向量，并将每篇新闻的向量、新闻标识及用于引用的必要元数据持久化到支持向量检索的 Redis 服务。向量数据、新闻缓存数据和 Agent 会话检查点 MUST 使用可区分的索引或键命名空间。

#### Scenario: 为新闻建立向量记录

- **WHEN** 系统为数据库中的新闻建立索引
- **THEN** 每篇可检索新闻在向量索引中都有一条可按新闻 ID 追溯的向量记录和必要引用元数据

#### Scenario: Redis 服务支持向量索引

- **WHEN** 应用初始化新闻向量索引
- **THEN** Redis 服务提供所需的搜索能力，且不会覆盖新闻缓存或 Agent 会话检查点的数据命名空间

### Requirement: 可重复的新闻索引构建

系统 SHALL 提供受控的全量新闻向量索引构建入口。重复执行该入口 MUST 以当前 `news` 表为准更新索引，且不得为同一新闻留下重复的可检索记录。

#### Scenario: 首次构建索引

- **WHEN** 管理员在空新闻向量索引上执行全量构建
- **THEN** 当前可检索新闻均可被后续语义查询召回

#### Scenario: 重复构建索引

- **WHEN** 管理员在已有索引上再次执行全量构建
- **THEN** 索引反映当前 `news` 表的数据，且同一新闻只保留一条有效可检索记录

### Requirement: 语义检索与关键词降级

系统 SHALL 优先根据问题与新闻向量的语义相似度返回有界的相关新闻及引用元数据。当本地 Embedding 服务、向量索引或索引数据不可用时，系统 SHALL 降级到现有关键词检索；降级过程 MUST NOT 向客户端暴露基础设施堆栈错误。

#### Scenario: 近义问题召回新闻

- **WHEN** 用户的问题与新闻表达语义相关但不包含相同关键词
- **THEN** 系统优先返回语义相关的有界新闻结果及其引用元数据

#### Scenario: 向量能力暂时不可用

- **WHEN** 本地 Embedding 服务、向量索引或索引数据不可用
- **THEN** 系统使用关键词检索继续尝试返回相关新闻，而不是因向量组件错误中断请求

#### Scenario: 两种检索均无结果

- **WHEN** 语义检索与关键词检索都未找到相关新闻
- **THEN** 系统返回空检索结果，且不得创建虚构新闻引用
